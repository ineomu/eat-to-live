## 🎯 我们欢迎什么

| 贡献类型 | 说明 | 例子 |
|---|---|---|
| **新增反模式** | 临床常见的饮食误区 | "早上喝果汁比可乐健康" |
| **新增慢病专项** | 在 `techniques.md` 里加新章节 | 骨质疏松 / 帕金森 / 阿尔茨海默 |
| **新增人群** | 在 `techniques.md` 里加人群适配 | 孕妇 / 婴幼儿 / 青少年 / 运动员 |
| **新增菜系食谱** | 跨地域饮食文化 | 印度素食 / 地中海 / 韩国 |
| **修正现有条目** | 提供更高级别证据 | 把 L4 升级到 L3 |
| **翻译** | 其他语言版本 | 日文 / 韩文 / 英文 / 西班牙文 |
| **测试用例** | 在 `tests/` 加新场景 | 任何"用户说 + AI 答"的真实案例（**请务必匿名化**：去掉姓名、城市、职业等可定位到真人的信息） |
| **Bug 报告** | 任何错误 / 歧义 / 不一致 | 数字错了、引用错了、逻辑漏洞 |
| **文档改进** | 让 SKILL.md / README / examples 更好懂 | 改一句话、补充一段 |

## 📐 提交规范

### Pull Request 模板

提交 PR 时，请使用以下模板（复制到 PR 描述里）：

```markdown
## 改动类型
- [ ] 新增反模式
- [ ] 新增慢病专项
- [ ] 新增人群
- [ ] 修正条目
- [ ] 翻译
- [ ] 测试用例
- [ ] Bug 报告
- [ ] 文档改进

## 改动内容
（简述改了什么 / 加了什么）

## 引用源
（必填，列出权威源 + 链接 / 章节 / 页码）

## 证据等级
（必填，标 L1-L5，见 references.md）

## 测试
（说明你怎么验证过这个改动是对的）

## 关联 issue
（如果有）
```

### 引用源要求

每个新增内容**必须**附上至少 1 个权威源：

| 内容类型 | 最少引用 | 推荐引用 |
|---|---|---|
| 反模式 | 1 个 L3 | 1 个 L3 + 1 个临床案例 |
| 慢病专项 | 1 份指南 | 1 份指南 + 1 本参考书 |
| 人群适配 | 1 份专项指南 | 1 份专项指南 + 1 个临床案例 |
| 食谱 | 1 份膳食指南 | 1 份指南 + 文化背景说明 |
| 翻译 | 原文对照 | 原文 + 2 个 native speaker 校对 |

### 证据等级（GRADE 简化）

```
L1：随机对照试验（RCT）+ Meta 分析
L2：队列研究 / 大样本观察
L3：专家共识 / 临床指南 / 权威机构推荐
L4：临床经验（个案 + 大量案例的规律总结）
L5：思维模型 / 操作口诀（便于记忆和执行的简化）
```

详见 `references.md` 第 4 节。

## 🔄 完整工作流

```
1. Fork 这个 repo
        ↓
2. 克隆到本地
   git clone https://github.com/YOUR_USERNAME/eat-to-live.git
        ↓
3. 创建分支
   git checkout -b feat/your-feature
        ↓
4. 写改动 + 引用源
        ↓
5. 加测试用例（tests/）
        ↓
6. 更新 CHANGELOG.md
        ↓
7. 提交 + 推送
   git commit -m "feat: 加 XX 反模式"
   git push origin feat/your-feature
        ↓
8. 提 PR
        ↓
9. 通过 review
        ↓
10. merge 到 main
```

## 💡 写反模式的模板

新增反模式时，请按这个格式（参考 `anti-patterns.md` 已有条目）：

```markdown
## DX. "反模式名"

**研究依据**：「研究/临床怎么说」

**真相**：
- 错误点 1
- 错误点 2
- 错误点 3

**应该怎么做**：
1. 操作 1
2. 操作 2
3. 操作 3
```

**好的反模式的特征**：
- 流传广（很多人信）
- 危害大（信了真的会出问题）
- 有反驳证据（不是凭空反对）
- 有替代方案（不只破，还立）

## 🤝 社区准则

- ✅ 友好、有耐心、欢迎新手
- ✅ 引用源要权威、具体
- ✅ 数字要精确（不要"适量"、"少许"）
- ✅ 涉及健康话题要谨慎（涉及急症/确诊疾病必须说"立即就医"）
- ❌ 不接受伪科学、未经验证的偏方
- ❌ 不接受没有引用的医学声明
- ❌ 不接受"某保健品能治 XX 病"的推广

## 🏷 版本管理

我们用 [语义化版本](https://semver.org/)：

```
主版本号.次版本号.修订号
  ↓       ↓      ↓
  重大变更  新功能  bug 修复
```

主版本号变更 = 不兼容的 API / 方法论变更（极少发生）  
次版本号变更 = 向后兼容的功能性新增（多数 PR）  
修订号变更 = 向后兼容的问题修正（小修小补）

提交 PR 时，请在 `CHANGELOG.md` 的 `[Unreleased]` 段加你的变更。
