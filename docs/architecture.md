# Architecture · 设计原理

> 解释这个 skill 为什么要这么设计，以及它是怎么工作的。

---

## 1. 核心问题

**"吃饭"是人类每天都在做的事，但它也是绝大多数慢病的根源。**

大多数人不知道：
- 自己每天到底吃了什么（结构）
- 食物在身体里怎么变成细胞
- 症状和饮食的因果关系
- 流行的"健康说法"哪些是真的

AI 大模型知道很多，但"营养教育"是个**需要 8 个信息才能开方**的领域——直接问"我该吃什么"会得到一个模糊答案。

**这个 skill 的目标**：让 AI 在用户问"吃饭"相关问题时，**自动进入一个高质量的临床营养问诊流程**，给出循证、个体化、可执行的建议。

---

## 2. 4 个入口的设计

为什么不做一个"全能入口"，而要分 4 个？

| 入口 | 用户的"心智状态" | AI 的响应 |
|---|---|---|
| 🚪 评饭 | "我刚吃完，给我看看" | 即时打分 + 一句话补法 |
| 🚪 反查 | "我身体有问题，是不是吃的原因" | 4 大组织 + 上中下游定位 |
| 🚪 拍砖 | "我听说 X 食物 Y 功效" | 26 条反模式库 + 引用反驳 |
| 🚪 体检 | "我想系统看看" | 5 分钟自测 + NCPM 4 步法 |

**为什么这么分**：
- 评饭：**轻量、即时**，不打断用户的日常节奏
- 反查：**症状驱动**，用户最焦虑的入口
- 拍砖：**辟谣驱动**，建立信任 + 升级认知
- 体检：**重量、深度**，需要用户主动投入时间

**原则**：**先匹配用户的心智状态，再决定走哪条路**。

## 3. 5 大元框架的来源

这 5 个框架不是凭空创造的，是从 3 个源头**层层筛选**出来的：

```
源头 1：临床营养学共识（NCPM、AND、DASH、WHO）
   │
   ↓ 提炼
源头 2：国内三甲医院临床营养科实践
（夏萌《你是你吃出来的》系列两册为代表）
   │
   ↓ 提炼
源头 3：本 skill 的 5 大元框架
```

| 框架 | 解决什么问题 | 为什么必进 |
|---|---|---|
| **七大营养素** | 万能盘点表 | 任何营养判断的起点 |
| **上中下游** | 慢病治理顺序 | 防止"只盯指标"的根本错误 |
| **NCPM 4 步法** | 标准化临床流程 | 国际通用的营养治疗流程 |
| **结构型 vs 能量原料** | 减肥/增肌的底层逻辑 | 解释"为什么减肥减错先掉肌肉" |
| **35% 动物 + 65% 植物** | 膳食结构金比例 | 一桌饭结构评估的金标准 |

## 5. 26 条反模式的设计逻辑

**为什么是 26 条不是 100 条**？

- 太多 → 记不住、查不动
- 太少 → 覆盖不全
- 26 条 = 12 大类 + 14 小类，**覆盖 90% 的常见误区**

**26 条的分类**：
- **养生类（6）**：D1-D6 — 流传最广、危害最大
- **减肥类（4）**：D4/D5/D24/D26 — 用户最多
- **食物类（7）**：D7-D13 — 具体食物的常见误解
- **早餐/吃饭习惯（3）**：D3/D15/D16 — 日常高频
- **医疗类（5）**：D17/D19/D20/D22/D25 — 慢病人群最危险
- **概念/伪科学（3）**：D6/D14/D23 — 难反驳但必须反驳

**每个反模式都包含 3 部分**：
1. **研究依据**（可信度）
2. **真相**（具体错在哪）
3. **应该怎么做**（替代方案）

## 6. 声音 + 比喻的设计

**为什么要有"人格"？**

AI 默认的回应"专业、平衡、礼貌到像客服"——但用户**不想要这种感觉**。

用户想要的是**临床医生门诊**的感觉：
- 见过真病例
- 直接、敢反驳
- 有比喻、有故事
- 给数字、给操作

**16 个比喻**的设计原则：
- **可视**（一秒钟能在脑子里画出画面）
- **日常**（用大家熟悉的东西）
- **准**（比喻能映射到机制）

**数字口诀**的设计原则：
- **压缩**（一个数字讲清一个原则）
- **复述**（用户能背出来才算掌握）
- **配操作**（不只是数字，还有"每天几次"）

## 7. 输出格式的强约束

**为什么强制格式**？

如果 AI 自由发挥，输出会五花八门。**统一格式的好处**：
- 用户预期稳定
- 关键信息不遗漏
- 便于后续 review

**5 条强制**：
1. 必须用数字口诀
2. 必须给权威依据
3. 必须给可执行
4. 必须排除 26 条反模式
5. 必须先调查再说话——渐进式：首轮声明假设给结果，结尾邀请补充，不甩问卷

## 8. 知识更新的机制

医学是不断更新的。这个 skill 怎么保持新鲜？

| 更新触发 | 频率 | 谁负责 |
|---|---|---|
| 国际/国内指南新版本 | 3-5 年 | 维护者 + 社区 PR |
| 收到错误反馈 | 实时 | 维护者 |
| 新增食物/营养素共识 | 实时 | 社区 PR |
| 新增慢病或人群 | 不定期 | 社区 PR |

**修订日志**写在 `CHANGELOG.md`，每条 PR 触发一次更新。

## 9. 边界与不做什么

**这个 skill 不做什么**：

- ❌ **不开药** — 涉及任何用药，AI 只能提示"听医嘱"
- ❌ **不替代医生** — 出现急性症状、严重异常，必须立即就医
- ❌ **不推荐保健品** — 涉及商业利益有偏见风险
- ❌ **不处理心理健康** — 焦虑/抑郁/进食障碍需要专业心理咨询
- ❌ **不涉及儿童处方** — 儿童的营养方案需要在专业指导下

**这个 skill 是**：**营养教育 + 生活方式建议 + 慢病饮食入门**。  
**这个 skill 不是**：**医生、营养师、医疗器械**。

## 11. 一句话总结

> **eat-to-live 不是营养学的"另一个版本"，是临床营养学共识的"开源实现"**。  
> 它不创造知识——它整理知识。  
> 它不开药——它给思考框架。  
> 它不替代医生——它让你在见到医生之前就知道问什么。

## 附录：决策树

用户进来时，AI 应该走哪条路：

```
用户提问
   │
   ├─ "我今天吃了 X"  ──────→  🚪 评饭
   │
   ├─ "我最近 Y 不舒服"  ─→  🚪 反查
   │                            │
   │                            ├─ 症状是急症？ → 立即就医
   │                            ├─ 症状是慢病信号？ → NCPM 4 步
   │                            └─ 信息不全？ → 反问 8 个关键信息
   │
   ├─ "我听说 W 食物"   ────→  🚪 拍砖
   │                            │
   │                            ├─ 匹配 26 条反模式？ → 引研究依据反驳
   │                            └─ 没匹配？ → 启动"先调查" + 要求出处
   │
   └─ "我想系统看看"   ──────→  🚪 体检
                                │
                                ├─ 5 分钟自测
                                ├─ 8 个关键信息
                                ├─ NCPM 4 步
                                └─ 给出 1 个月内优先解决 3 件事
```
